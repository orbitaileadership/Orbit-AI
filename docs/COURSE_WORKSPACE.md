## Course folders — October 19, 2026

The main chat sidebar lists **Folders**, separated into pinned folders and recent folders. A folder groups chats and reusable files and can optionally belong to one course. A course can contain multiple folders, such as one folder per assignment. Create, rename, assign/reassign, pin/unpin, open, and manage folder files through the folder list. The course workspace exposes its own Folders tab and an overview shortcut. Opening a folder starts an unsent chat draft and shows its existing chats for the selected assistant. Orbit also lists pinned/recent folders and filters its conversations by folder.

Migration `0018_course_folders.sql` is required before releasing this version. It adds folder metadata to the existing projects table and retains the existing chat/file relationship and RLS paths. Existing project records remain courses; no course, conversation, or file is moved or deleted by the migration. New folder rows cannot carry syllabus metadata, cannot contain other folders, and can only reference a course owned by the same user. Deleting a parent course detaches its folders rather than deleting them. Pins and last-opened timestamps are stored in the account, shared across providers and devices. Folder chats use the existing folder's instructions and files; parent-course materials are not automatically copied or added to AI context.

This change is prepared locally only. The migration has been exercised in an isolated synthetic database; it has not been applied to the shared database. Signed-in staging validation remains required before release.

## Assignment workspaces — October 19, 2026

Each assignment in a course can have its own workspace: a folder inside the course (existing `projects` row, `is_folder`, `parent_course_id`), created on the first upload or chat from the assignment page, never by just opening it. The assignment item stores `folderId` in the course's `course_data`; `PATCH /api/courses/[id]`, syllabus confirm and revision merge keep it only when it is the student's own folder inside that course (`lib/courses/assignment-folders.ts`), carry an existing link over when an edit comes from an older screen, and never accept it from model extraction. `GET/POST /api/courses/[id]/assignments/[itemId]` returns or creates the folder (optimistic version check, one retry, cleanup of a losing folder) with its files and chats.

The assignment page shows the assignment's chats (any of the four AIs or Orbit, chosen with the course's "Ask with" picker), its files (drop zone, colour-coded file cards, open/remove) and the course files the AI can also quote. Chats in a folder that belongs to a course now also receive the parent course's details, preferences, syllabus and notes: `courseContext` (chat and Orbit) searches the folder's files first, then the course's, inside the same 1,600-token passage cap, with folder/assignment names kept inside the untrusted JSON reference; `gatherMaterial` adds the parent course's files and labels "Files in this folder" vs "Files in its course". Folders outside a course and plain course chats behave as before. Orbit still sends only bounded text excerpts, now possibly including the parent course's, to all four providers (existing disclosure applies).

No migration. Second-model review (Sonnet subagent) found no cross-student access path; its HIGH finding (a status change from a stale screen dropped the link) and the prompt-fence, file-crowding and labelling findings were fixed with regression tests. Signed-in staging validation of uploads, chats and live answers remains pending.
