# Courses C7 backend optimizer — offline audit

Date: 2026-11-15. Baseline: `0a70fd1cba381bbb5c6cb9b7d1cebfbd7dfa340e`.

## Scope and result

Documentation-only, public-source audit of launched Courses MCQ, short-answer and flashcard output validation. No application, test, prompt, model, provider, accounting, database or migration changes; no network/provider calls, database actions, deployment, branch changes or external messages. Private/held-out evidence and `.feedback-runs` were not read. No telemetry was needed or consumed. Root owns dependencies and checks. C5 exhausted-score safeguards and C6 visible-deck export parsing remain untouched; Orbit O6 owns route cleanup.

**Finding:** `hasInteractiveStudySet` accepts a response if *any* parsed study widget has the requested format and count. It does not reject additional valid study widgets. A requested one-question MCQ followed by another MCQ or flashcard deck therefore passes the launch gate. This is a structural contract gap, not evidence of incorrect subject answers or observed live frequency.

**Recommendation:** a minimal pure-validator tightening is warranted if C7's contract is exactly one requested study set. Collect validated study widgets from the existing bare-JSON/fenced candidates, require exactly one, then check its type and exact item count. Keep `parseWidget` as the schema authority. Do not change routing, prompts, model choice, retry policy, output caps or accounting. Root decides and implements the candidate; this report changes no validator code.

## Routing, retries, tools and all-call economics

- **Standard chat:** preserves the selected enabled provider/model. `app/api/chat/route.ts:454` reserves before its stream; a failed reservation can retry reservation with a smaller useful output cap before any model call. This is not a second purchased answer. Explicit user retries and tool continuations are new billable attempts and must remain included in evaluation totals. Settlement at `:569` uses actual returned usage, safe release for qualifying pre-stream failures, or uncertain settlement. Invalid study output still incurred its provider cost; the validator does not refund it.
- **Tools:** the Courses client disables explicit web/code/plugins/skills/folder use for quiz sends (`app/chat/chat-app.tsx:774`–`:799`). Server offering remains broader: automatic search can still be offered when live, configured, non-course-only and otherwise eligible (`app/api/chat/route.ts:346`). Do not infer zero research cost from the client flags. Tool rounds retain `MAX_TOOL_STEPS = 12`, `MAX_CALLS_PER_STEP = 8` (`lib/folder/tools.ts:102`), shared context fitting and their own answer reservations. Search uses a per-question ledger identity, reserves/reconciles separately, and stores both success and failure to avoid buying another search silently (`app/api/chat/route.ts:240`–`:301`). Tool execution/plugin service costs cannot be inferred from the validator.
- **Auxiliary calls:** long-history summary (`lib/chat/summary.ts:101`) and consent-gated retrieval embeddings (`lib/chat/retrieval.ts:28`) each reserve and settle separately. Include them, query/index embeddings and failed/uncertain attempts in an all-call comparison. They are not removed by a pure validator change. Disclosed context omission, summary coverage and citation safeguards must remain.
- **Orbit:** preserves configured voter/candidate identities and ballots, rather than silently replacing a failed lead. Four voter attempts, one lead, possible specialist, possible summary and allowed Google retry/fallback all contribute cost. `lib/orbit/call.ts:28` creates a separately reserved ledger row per paid phase; settles usage/failure before requiring nonempty `stop` output. Google eligible pre-stream 503 retry remains bounded by its original deadline and helper cap (`app/api/orbit/route.ts:171`–`:210`). Configured helper cap is 150,000 USD micros, specialist output 900, ballot output 256, answer output 4,000, input cap 8,000 (`config/orbit.ts`); these are bounds, not measured costs or quality claims. No browsing/execution tools are offered by the Orbit lead path. Do not alter these controls in C7.
- **Accounting semantics:** `lib/billing/budget.ts:41` documents settled = actual charge, uncertain = full reservation, released = zero. Failed settlement leaves the reservation counted. A final visible answer cost or successful-call-only average is not all-call economic evidence.
- **Evaluation:** `lib/eval/accounting.ts` requires a dedicated tester and positive run cap, enforces provider availability, reserves each evaluation call with run linkage, and reconciles after it. `benchmarks/quality.eval.ts` loops baseline/candidate/repeats with this wrapper. Its prompt-baseline comparison is not a C7 validator experiment; it bypasses the app's launch/save/routing journey. `lib/eval/quality.ts:128` records zero display cost when usage is absent, while accounting may hold an uncertain reservation: that summary alone cannot prove zero spend. No eval was executed.
- **Development and agent work:** no local provider/eval calls were made for this audit. This agent's own service cost is not supplied through the repository's call ledger and is unknown here, not proven zero. Future all-call assessment must include or explicitly reconcile development agents, auxiliary/judge/evaluation calls and repeated failed/rejected generations; supplied offline fixtures cannot establish those totals.

## Minimal candidate acceptance and risks

Keep existing bare JSON and valid JSON-fence normalization, exact count, schema bounds, ordinary surrounding prose and non-study content compatibility. Reject two validated study widgets even if one alone matches: same type, other type, identical duplicate, wrong-count extra or reverse order. Reject no valid study widget, wrong-only type/count, malformed-only JSON and invalid MCQ keys. Exercise MCQ, short-answer and flashcards independently. Preserve valid single-set behavior at counts 1 and 30. Root should add focused pure-validator cases and run applicable checks; no new tests were written in this audit.

The smallest change counts **validated** study widgets. It will not reject extra malformed study-looking JSON that never becomes an interactive widget, nor establish answer correctness. Counting every arbitrary JSON/code block would expand scope and could reject legitimate explanation content. Use the existing candidate extraction without duplicating a bare object; do not sum separate decks to satisfy the requested count. Exact uniqueness is a product-contract tightening, so malformed extras and non-study widgets should be an explicit acceptance choice rather than accidental policy.

Rejecting mixed/duplicate output can increase explicit user retries and paid cost even if it reduces misleading success states. No evidence here shows frequency, quality parity, retry rate, latency or savings. Existing case-insensitive validator fence recognition and renderer's canonical `orbit-widget` handling also deserve focused compatibility coverage; avoid a fence-normalization refactor as part of this fix.
